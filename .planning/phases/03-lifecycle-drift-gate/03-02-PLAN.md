<threat_model>
ASVS baseline: Level 1. Risk threshold: any unresolved high-severity threat blocks plan completion.

## Trust Boundaries

| Boundary | Description |
|---|---|
| Git/tool evidence → classifier | Git and capability probe outputs are untrusted, may fail, timeout, truncate, or describe a different repository/state, and cannot be accepted as partial success. |
| manifest/repository evidence → composite observation | Manifest bytes, mapping readiness, phase graph, and canonical-source evidence may be individually valid yet mutually inconsistent. |
| prior decision evidence → operation admission | A previously valid decision identity may be replayed after any admission-relevant input changes. |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03-05 | Spoofing/Tampering | high | Git/tool evidence → classifier | mitigate | Require exact typed results, bounded complete output, repository/change/source-commit agreement, and exact capability equality; failure, timeout, truncation, or malformed evidence becomes unknown. |
| T-03-06 | Tampering/Elevation of Privilege | high | composite lifecycle gate | mitigate | Admit only the conjunction of all required evidence domains through one public seam; reject unknown/drifted operation or target values and prohibit partial-green projection. |
| T-03-07 | Tampering/Repudiation | high | prior decision evidence → operation admission | mitigate | Recompute a versioned length-prefixed SHA-256 identity from the entire current observation and compare exact lowercase identities in constant time; stale or malformed evidence never admits. |
| T-03-08 | Denial of Service | high | manifest, phase graph, and tool observations | mitigate | Apply existing manifest limits plus explicit count/aggregate bounds; over-limit and truncated inputs are unknown with no partial digest or partial result. |
| T-03-09 | Repudiation | medium | deterministic blocking evidence | mitigate | Frozen decisions contain the operation, target phase, state, unique sorted stable issue codes, and a decision identity only for complete observations. |
| T-03-SC | Tampering | low | package supply chain | accept | No package install or dependency change occurs; standard-library hashing/comparison and existing project dependencies are reused. |
