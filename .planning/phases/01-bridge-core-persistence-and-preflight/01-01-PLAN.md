<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| change ID / candidate JSON -> functional core | Untrusted identifiers, schema values, counts, paths, and state enter typed validation. |
| repository filesystem -> bounded reader | Paths may traverse or resolve through symlinks; bytes may be malformed or oversized. |
| candidate route -> fallback route | Partial values can cross-contaminate a fresh discovery result unless builders are isolated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering / Information Disclosure | `reader.py` containment | mitigate | Resolve repository/change/artifact paths, require regular Markdown inside both roots, and hash the one verified byte buffer. |
| T-01-02 | Denial of Service | `reader.py`, `progress.py` | mitigate | Enforce source-pinned count and byte limits with limit-plus-one reads and fail the whole operation without truncation. |
| T-01-03 | Tampering / Repudiation | `discovery.py` route adoption | mitigate | Validate a whole candidate, use route-local builders, and prove fresh fallback with poisoning tests. |
| T-01-04 | Elevation of Privilege | `discovery.py` inputs | mitigate | Keep subprocess and shell execution outside this plan's pure discovery API. |
| T-01-SC | Tampering | package installs | accept | No dependency or install task exists in this plan; repository-pinned stdlib and existing dev tools only. |
</threat_model>
