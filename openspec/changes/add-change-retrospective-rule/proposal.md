# change close 時の軽量ふりかえり規約を追加する

## Why

バックログ #11（バグ削減の未採用注入点 3 つ: 契約 / 敵対的仕様攻撃 / mutation testing）は
「仕様時列挙＋PBT を先行させ、効果測定後に判断」と確定済みだが、**測定手段が未定義**のため
判断時期が永遠に来ない（バックログ #18）。

- 現状、change のマージ後に「どの欠陥がどのゲートまで逃げたか」を記録する場所が無く、
  spec-holes / self-review / クロス AI レビュー / CI の各ゲートの補足率が事後に再構成できない
  （PR コメントに散在し集計不能）。
- 必要なのは重い計測基盤ではなく、**change close 時に 1 行残す記録先と固定形式**
  （逃した欠陥の件数と発見経路）だけ。それがあれば #11 の判断材料は自然に蓄積する。

## What Changes

docs のみの変更（コード変更なし・機械ゲート追加なし）:

- **docs/agents/workflow.md**: 「change close 時の軽量ふりかえり」節を新設し、
  記録先・1 行形式・「逃した欠陥」の定義・発見経路 4 分類・更新規則（マージ後発見分の
  遡及追記・1 change = 1 行維持）・適用範囲（テンプレート自身の change 運用のみ・下流は任意）
  を規定する。
- **docs/template/retrospectives.md**: 記録先ファイルを新規作成する（ヘッダのみ。
  エントリは各 change の close 時に追記される。`docs/template/` 配下のため
  prune-template-docs の削除対象＝下流にデータが漏れない）。
- **openspec/project.md**: 「テンプレート自身の change 運用」節に close 時ふりかえりの
  1 行（workflow.md への参照）を追記する。

spec delta は `changes/add-change-retrospective-rule/specs/change-retrospective/spec.md` に
置く（engine のデルタ必須要件を満たす。close 時削除で `openspec/specs/` 出荷時空を維持）。

## 設計判断

1. **記録先はリポジトリ内ファイル（docs/template/retrospectives.md）**。GitHub 非依存の
   中立記録（add-execution-tracking-rules と同方針）で、集計は 1 ファイルの目視 / grep で
   足りる。PR body 案は post-merge 発見分の追記先が散らばるため不採用。
   `docs/template/` 配下に置くことで、テンプレ自身の運用データが下流へ漏れない
   （prune-template-docs が一括削除・ADR-0006 の隔離方針と整合）。
2. **形式は固定 1 行**。`- YYYY-MM-DD <change-id>（PR #N）: 逃した欠陥 <計> 件
   （self-review=a / review=b / CI=c / merge後=d）— 一言（任意）`。
   発見経路は 4 分類固定: `self-review`（自己 diff 検査）/ `review`（自分以外のマージ前
   レビュー。Codex クロス AI・人間を問わない）/ `CI`（自動チェックの赤）/ `merge後`
   （マージ後に発見された欠陥全般。revert 含む）。
3. **「逃した欠陥」の定義は「実装 task の完了マーク後に発見され、修正を要した正しさ・
   仕様不一致の欠陥」**（docs の事実誤りを含む）。実装中の自己修正は数えない。
   style nit・主観的リファクタ提案・回答のみで済む質問は数えない。同一欠陥は最初に
   発見された経路でのみ数える（重複カウントしない）。境界の判断は記録者に委ね、
   迷った場合は一言欄に補足する（軽量規約・厳密な判定機構は持たない）。
4. **0 件でも記録する**。記録の不在が「欠陥ゼロ」か「記録忘れ」か区別できなくなるため。
5. **機械ゲートは追加しない**。形式検査・記録漏れ検出の自動化はしない（重い仕組み不要が
   要件。backstop は self-review の AGENTS.md / 規約適合チェックと人の目視）。
6. **適用はテンプレート自身の change 運用のみ**。workflow.md は下流にも ship されるため
   節内で適用範囲を明示し、下流リポジトリは任意採用（採用時は自分の記録先を決める）とする。

## spec-holes フェーズ 1 の穴リスト

確定前にタクソノミー 12 分類 × 4 要件を全数当て、該当 13 件を「1: 仕様に明記」10 件・
「2: スコープ外と明記」3 件で潰した（ユーザ確認を要するトレードオフなし）。
self-review 時はこのリストと spec delta を突き合わせる。

| 穴 | 分類 | 潰し方 | 潰した場所 |
| --- | --- | --- | --- |
| H1 欠陥 0 件の change | R1×空 | 1: 0 件でも記録・一言欄は省略可 | R2 本文 |
| H2 行記入後〜マージまでの発見 | R1×境界値 | 1: マージ前発見は該当経路へ行を更新 | R3 Scenario |
| H3 同一 change の行が既に存在 | R1×重複 | 1: 既存行を更新・新行を足さない | R3 本文 |
| H4 エントリの並び順 | R1×順序 | 1: ファイル末尾へ追記（時系列） | R1 本文 |
| H5 形式逸脱の機械検査 | R1×型 | 2: スコープ外（backstop は self-review） | 設計判断 5 |
| H6 記録忘れのままマージ | R1×エラー経路 | 1: 気づいた時点で遡及追記可 | R1 Scenario |
| H7 日付の基準 | R1×時刻 | 1: close 時のローカル日付（厳密性不要） | R1 本文 |
| H8 1 行厳守（改行） | R1×文字列 | 1: 改行しない（1 change = 1 行） | R1 本文 |
| H9 エントリの蓄積 | R1×巨大入力 | 2: スコープ外（rotate は将来判断） | 設計判断 5 相当・Non-goals |
| H10 破棄された change / revert | R1×状態遷移 | 1: 破棄は対象外・revert は merge後に計上 | R2/R3 本文 |
| H11 「実装完了後」の起点 | R2×境界値 | 1: 実装 task の完了マーク時点 | R2 本文 |
| H12 同一欠陥の複数経路発見・nit との境界 | R2×重複/型 | 1: 初回経路のみ・定義と除外列挙・迷いは一言欄 | R2 本文 |
| H13 原因 change を特定できない merge後欠陥 | R3×型 | 1: 特定できる場合のみ帰属（無理に帰属しない） | R3 本文 |

フェーズ 2（テスト化）: docs のみの規約で実行時サーフェスが無く、機械ゲートも
意図的に持たない（設計判断 5）ため、全穴を「未検証（docs 規約・機械検証対象外）」とする。
backstop は self-review の突き合わせ。

## 受け入れ基準

- [ ] workflow.md の新節に、記録先・1 行形式・欠陥定義・経路 4 分類・更新規則・
      適用範囲（テンプレ自身のみ・下流任意）が規定されている。
- [ ] docs/template/retrospectives.md がヘッダ付きで存在し、形式の owner を workflow.md に
      委譲している（形式定義を二重化しない）。
- [ ] openspec/project.md の「テンプレート自身の change 運用」に close 時ふりかえりの
      1 行参照がある。
- [ ] `task check` が green。
- [ ] `task openspec:validate` が green。
- [ ] close 時、本 change 自身のふりかえり行が retrospectives.md に記録される（dogfood・初エントリ）。

## Non-goals

- **記録の機械検査・集計自動化**（形式 lint・記録漏れ検出・統計スクリプトは作らない。
  必要になったら別 change）。
- **#11 の 3 注入点の採否判断**（本 change は測定手段の定義のみ。判断はデータ蓄積後・人起点）。
- **ログの rotate / アーカイブ規約**（蓄積が問題になったら将来判断）。
- **下流リポジトリへの適用強制**（規約はテンプレ自身の運用。下流は任意採用）。
- **spec-holes / self-review 等の各ゲート自体の変更**（測定して判断材料を得るのが目的で、
  ゲートの中身は触らない）。
