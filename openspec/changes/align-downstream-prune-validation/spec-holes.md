# spec-holes: 12分類監査と検証対応

文書種別: 仕様リファレンス。DPV-1〜DPV-6の全要件に12分類を適用した。
初稿の「未解決判断なし」は、レビューで manifest・直接参照・履歴リンクの未定義を指摘された。
再対話で保守文書15件・保守テスト3件の必須性、直接参照の保証範囲、JSON fixture、
Markdown のコマンド判定、履歴 link target 限定修正を合意した。
第3回レビュー後、R01 は既存 canonical validator 成功後の構文だけを扱う方針へ修正した。
Taskfile dir の受理、cwd 解析限界による一律拒否、固定 root 初期化例外は撤回した。
workflow の静的 cwd は解決し、動的 cwd / shell 内移動の影響範囲は未評価として別報告する。
未評価だけで gate / doctor / apply を失敗させず、判定可能な専用参照・既存契約違反の拒否は維持する。
以上は実装開始前に確定した判断である。実装・検証の現在の進捗は tasks.md を参照する。
外部レビュー後の改訂案と未解決判断は末尾に分け、既存の確定仕様と混同しない。

「該当」は仕様に挙動を明記済み（解消方法1）。保証対象外の記載は解消方法2を併用する。
「非該当」も理由を明記する。検証IDは [validation.md](validation.md) を参照する。
表は検証条件との対応を示し、実行結果・完了状態は tasks.md だけで管理する。
2026-10-15に DPV-1〜6 × 12分類の全72行を再監査し、影響がある行へ「改訂案」を追記した。
追記のない行は既存判断を維持する。時刻による選択、研究数値・乱数処理等は追加しないが、
DPV-3 の位置 protocol は整数・範囲の契約があるため分類10を該当へ変更した。
追記は2026-10-15に改訂全体として承認され、design §8 と spec delta の規範へ統合した。
表内の仕様は [spec delta](specs/downstream-prune-validation/spec.md) と [design.md](design.md) の具体化であり、
独立した実装指示や完了証拠ではない。
